## 0. Цель этапа

v0.5.0 закрывает ядро продукта: цикл обучения ученика, управляемый чат и
песочницу, самообслуживание аккаунта, разбор работ учителем и обзор
действий у администратора. v0.6.0 добавляет **глубину вовлечения**,
**доступность и устойчивость интерфейса** и закрывает **оставшийся риск
безопасности сессий**.

### 0.1. Критерии успеха этапа

| Критерий | Проверяемое доказательство |
|----------|-----------------------------|
| Ученик видит траекторию обучения | страница «Траектории», прогресс по каждой траектории, placement-тест при первом входе |
| Прогресс виден как достижения, рейтинг и сертификат | галерея достижений с прогрессом, лидерборд класса (скрыт по умолчанию), сертификат с идентификатором проверки |
| Приложение не «ломается» | `ErrorBoundary` на маршрутах, экран ошибки вместо белого полотна, тест на падение рендера |
| Понятная работа при плохой сети | различение 401/429/5xx, backoff для идемпотентных GET, индикатор «нет соединения» |
| Устанавливается как приложение | `manifest.webmanifest`, service worker, offline-страница, установка без HTTPS не ломает работу |
| Удобно на телефоне | нижняя навигация, карточки вместо таблиц на 360 px, скриншоты в отчёте |
| Доступность и переводы | a11y-аудит всех экранов без critical, `check-i18n` зелёный, `aria-live` для стриминга и уведомлений |
| Токены не в `localStorage` | httpOnly-cookie + CSRF double-submit, `KI-027` закрыт |
| Документация | `SPEC`, `UPGRADE`, `USER_GUIDE`, `CHANGELOG`, `RELEASES`, отчёты по шагам и спринтам |

### 0.2. Принципы этапа

1. **Не ломать то, что работает.** v0.6.0 не меняет продуктовые сценарии
   v0.5.0, а добавляет траектории, доступность и безопасность.
2. **Приватность по умолчанию.** Лидерборд скрыт, сертификат не публикуется
   без действия пользователя, placement-тест можно пропустить.
3. **Устойчивость вместо оптимизма.** Любая сетевая ошибка имеет
   пользовательский сценарий, а не трассировку в консоли.
4. **Cookie/BFF — отдельным спринтом.** Безопасность сессий не смешивается
   с продуктовыми задачами: сбой в одном не должен ломать другое.
5. **Один источник правды.** Детали задач — здесь; `RELEASES.md` хранит
   статус, `README.md` — навигацию.

### Спринт 51: Auth Hardening — httpOnly-cookie/BFF — `[ ]`

**Цель:** токены больше не лежат в `localStorage`: доступ и refresh хранятся
в httpOnly-cookie с CSRF-защитой. Закрывает `KI-027`.

**Зависит от:** v0.5.0 спринт 45 (`token_version`, управление сессиями),
спринт 50 (устойчивость клиента)
**Оценка:** 2,5 дня
**Закрывает:** `KI-027`
**Отчёт:** `docs/reports/sprint-51/SPRINT-51.md`

#### S51-001: Схема cookie и CSRF — `[ ]`

- [ ] Флаги `AUTH_TOKEN_TRANSPORT=cookie|bearer` (по умолчанию — `bearer`,
      переключение — конфигурацией, миграция без простоя) и
      `AUTH_COOKIE_SECURE`.
- [ ] Cookie: имя `__Host-` (в проде) / `ai-teacher-at` (dev), `HttpOnly`,
      `SameSite=Strict`, `Secure` в проде, `Path=/`; access — 30 мин,
      refresh — 7 дней (как сейчас).
- [ ] CSRF: double-submit — отдельная cookie `csrf_token` (readable из JS) +
      заголовок `X-CSRF-Token`; проверка на всех изменяющих запросах.
- [ ] Тесты: cookie недоступна из JS, CSRF-токен обязателен для POST/PATCH/
      DELETE, запрос без CSRF → 403, refresh по cookie работает.
- [ ] **Зависит от:** — · **Оценка:** 8 ч

#### S51-002: Перевод API и клиента — `[ ]`

- [ ] `get_current_user` принимает Bearer **или** cookie; при `cookie`
      Bearer-путь сохраняется для CLI и интеграций.
- [ ] `POST /auth/login` и `/auth/refresh` выставляют cookie; `POST
      /auth/logout` очищает их.
- [ ] Клиент: `lib/token.ts` перестаёт хранить access/refresh в
      `localStorage`; `api.ts` — `credentials: 'include'`; `lib/chatSocket`
      — авторизация WebSocket через cookie (query-токен не используется).
- [ ] Nginx: `proxy_set_header X-Forwarded-Proto`, обработка CSRF-заголовка,
      проверка, что `Authorization` не пересекает границу при `cookie`.
- [ ] Тесты: e2e «логин → действия → логаут» в режиме `cookie`;
      контрактные тесты OpenAPI обновлены.
- [ ] **Зависит от:** S51-001 · **Оценка:** 8 ч

#### S51-003: Откат и документация — `[ ]`

- [ ] `AUTH_TOKEN_TRANSPORT=bearer` — рабочий откат одной переменной;
      проверено в тестовом окружении.
- [ ] `docs/KNOWN_ISSUES.md`: `KI-027` → Closed с датой и ссылкой на PR.
- [ ] `docs/ARCHITECTURE.md` и `docs/PRIVACY.md`: где хранятся токены, что
      попадает в cookie, порядок отзыва сессий.
- [ ] **Зависит от:** S51-002 · **Оценка:** 4 ч

**DoD:** Bearer в `localStorage` не используется в режиме `cookie`; CSRF
работает и покрыт тестами; логин/refresh/logout и WebSocket работают с

## 7. Риски и меры

| Риск | Вероятность | Влияние | Мера |
|------|-------------|---------|------|
| Смена схемы авторизации ломает клиент или WebSocket | Средняя | Высокое | Флаг `AUTH_TOKEN_TRANSPORT`, оба режима покрыты тестами, откат проверен до релиза (S51-003) |
| CSRF-токен в cookie и `SameSite=Strict` конфликтуют | Низкая | Среднее | Отдельные cookie (double-submit), тест на cross-origin POST |
| PWA/service worker конфликтует с деплоем (stale assets) | Средняя | Среднее | Версионирование кэша SW, `skipWaiting` по решению, проверка на staging |
| Лидерборд воспринимается как «список отстающих» | Средняя | Среднее | Скрыт по умолчанию, режим «по месяцу», без оценок «худших» |
| Placement-тест отпугивает нового ученика | Средняя | Низкое | Мастер пропускается, уровень можно переопределить вручную |
| Настройки доступности конфликтуют с темой | Средняя | Низкое | CSS-переменные, режим «высокий контраст» как отдельный слой поверх темы |
| Отсутствие глобального поиска (в бэклоге) | Средняя | Низкое | Поиск по задачам (S42-004) и по истории чата уже есть |
