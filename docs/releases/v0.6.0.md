# v0.6.0 — Production Hardening

**Дата:** 2026-11-12 · **Тег:** `v0.6.0` (создан и запушен) · **Предыдущий:** `v0.5.0`
**Тип релиза:** single-node · **Обратная совместимость:** частично —
`POST /auth/refresh` принимает `refresh_token` только в теле JSON
**Схема БД:** head `022` (новых миграций в v0.6.0 нет)

v0.6.0 переводит продукт на **архитектуру Production Hardening**: вместо
сборки на VPS — воспроизводимые образы из GHCR с digest-пиннингом, вместо
открытого HTTP — Caddy с TLS/ACME, вместо ручных бэкапов — ежедневный
systemd-таймер с age-шифрованием и S3, вместо «наблюдаемости по логам» —
Prometheus/Grafana/Sentry/SLO. Это релиз **эксплуатационной и security-
готовности**, а не новых пользовательских функций.

## Главное

### Блокеры DevOps-аудита закрыты

- **Воспроизводимый артефакт и registry:** `docker-publish.yml` публикует
  backend/frontend/sandbox-runner в **GHCR** по тегу `v*`; prod-compose без
  `build:`, образы подставляются по digest (`scripts/pin_images.sh`),
  `scripts/rollback.sh` возвращает предыдущее состояние.
- **TLS и edge:** **Caddy** — единственный публичный слушатель: ACME/TLS,
  WebSocket/LLM-стриминг, HSTS/CSP/security-headers, лимит тела 10 МБ и
  таймауты upstream. Backend/Postgres/Redis наружу не публикуются.
- **Автоматические бэкапы:** `scripts/backup.sh` (gzip + **age** + **S3**),
  systemd unit/timer (03:00 UTC), retention 14 дней, метрика
  `backup_last_success_timestamp`; восстановление — `restore.sh` и
  `restore_drill.sh`.
- **High-риски безопасности:** refresh-токен только в теле запроса
  (query удалён), `TRUSTED_PROXIES` и корректный `X-Forwarded-For`,
  `require_role` проверяет `is_active` (деактивированный — 401), per-user
  rate limit, fail-fast при небезопасном `SECRET_KEY`, `DOCS_ENABLED=false`
  в prod.
- **Наблюдаемость:** `UVICORN_WORKERS=2` с multiprocess-метриками,
  Prometheus-алерты/recording rules, Grafana «AI Teacher — Overview»,
  Loki/Promtail, Sentry без PII, `docs/SLO.md` и `docs/MONITORING.md`.
- **CI-гейты:** preflight раннера, coverage 70% (backend/frontend), паритет
  GitHub/GitFlic, локальные `gates.sh`/`gates.ps1`, env-drift
  `Settings ↔ .env.example`.
- **Безопасность детей:** ASVS L1 self-assessment, аудит и DPIA, guardrails
  LLM (prompt injection/токсичность, защитные инструкции в промптах).
- **Производительность:** нагрузочные сценарии health 20 / tasks 10 /
  submit 5 RPS, nightly + baseline, query-count тесты против N+1, кэш
  `/admin/quality` с инвалидацией, лимит загрузок `MAX_UPLOAD_BYTES` (413/415).
- **DX:** ADR-001…007, `CONTRIBUTING.md`, CODEOWNERS, шаблоны issue/PR.

### Готовность к пилоту

Согласно [DEVOPS_AUDIT_2026-11.md](../reports/DEVOPS_AUDIT_2026-11.md), после
выполнения перечисленных мер продукт **допустим к безопасному закрытому
пилоту в режиме single-node**.

**Публичный production пока не разрешён.** Для него нужны отдельный VPS и
домен, юридическая проверка (152-ФЗ), multi-node/HA и DR-SLO 2.0,
e-mail-подтверждение/сброс пароля (`KI-035`) и полная модерация ответов LLM
(`KI-036`, v0.7.0). Подробности — аудит и [RUNBOOK.md](../RUNBOOK.md).

## Обновление

- Новых миграций нет: схема остаётся на head **022**. Достаточно обновить
  код/образы и переменные окружения.
- **Breaking:** `POST /auth/refresh` — только JSON-тело
  `{"refresh_token": "..."}`; query-вариант удалён. Клиенты v0.5.0 нужно
  обновить вместе с backend.
- Новые ENV: `TRUSTED_PROXIES`, `SENTRY_*`, `DOCS_ENABLED`,
  `LLM_GUARDRAILS_ENABLED`, `MAX_UPLOAD_BYTES`, `*_FILE`,
  `RATE_LIMIT_ENABLED`, `UVICORN_WORKERS`/`PROMETHEUS_MULTIPROC_DIR`.
- Порядок обновления, digest-деплой и оба сценария отката —
  [UPGRADE.md](../UPGRADE.md) §0.3.1, §0.5, §0.7.1.

## Откат

Рекомендуется **откат только кода** на `v0.5.0`: новых миграций не было,
схема совместима, данные сохраняются. Если клиенты ещё не обновлены, откат
выполняется вместе с frontend v0.5.0 (refresh снова в query).

```bash
# прод: вернуть предыдущие образы из .last_deploy
bash scripts/rollback.sh --dry-run   # план
bash scripts/rollback.sh             # откат + healthcheck

# вручную: checkout тега и перезапуск
git checkout v0.5.0
docker compose -f docker-compose.prod.yml up -d
```

Полный откат схемы не требуется; при потере данных — `scripts/restore.sh`
(поддерживает `*.age`). Подробно — [UPGRADE.md](../UPGRADE.md) §0.6,
[RUNBOOK.md](../RUNBOOK.md) §5.
