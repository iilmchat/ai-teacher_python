# v0.6.1 — Deploy Fixes

**Дата:** 2026-11-13 · **Тег:** `v0.6.1` · **Предыдущий:** v0.6.0
**Миграции:** head `022` (без изменений) · **Продуктовый код не менялся.**

Патч-релиз по итогам первого production-деплоя (VK Cloud, пилот
`teacher.iiruchating.ru`). Устранены два блокера, из-за которых контейнер
не поднимался или не мог обратиться к LLM.

## Исправлено

### TRUSTED_PROXIES

Поле объявлено как `Annotated[list[str], NoDecode]`, но валидатора для
строки не было. Любое значение в ENV (CSV, JSON, пустая строка) вызывало:

```
pydantic_core.ValidationError: trusted_proxies
  Input should be a valid list
```

Backend падал на старте, healthcheck не проходил. Добавлен разбор CSV и
JSON-массива — как у `allowed_origins`.

### DEEPSEEK_MODEL

Модель была захардкожена (`DeepSeekProvider()` → `deepseek-chat`). Для
OpenAI-совместимых агрегаторов нужен префикс (RouterAI:
`deepseek/deepseek-chat`), иначе провайдер отвечает
`Model 'deepseek-chat' not found`.

- добавлено поле `deepseek_model` (default `deepseek-chat` — обратная
  совместимость сохранена);
- фабрика передаёт модель в `DeepSeekProvider`;
- `DEEPSEEK_MODEL` проброшен в `docker-compose.prod.yml` и примеры env
  (`.env.example`, `.env.prod.example`).
