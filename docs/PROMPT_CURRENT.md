# PROMPT_CURRENT — актуальные системные инструкции и метрики

Документ для тех, кто работает с ассистентом (LLM) и для DSH: что именно
уходит в модель сейчас.

**Версия промптов:** basic v1, intermediate **v2**, advanced v1 · **Обновлено:** 2026-10-29 (спринт 13)

---

## 1. Где лежат промпты

```
backend/app/services/llm/prompts/
├── basic.txt          # базовый уровень
├── intermediate.txt   # средний уровень
├── advanced.txt       # продвинутый уровень
└── versions.json      # версия каждого уровня (S12-006)
```

Загрузка: `app/services/llm/prompt_builder.py::load_system_prompt` (с кэшем).
Версия: `load_prompt_versions()` / `prompt_version(level)`; попадает в
`chat_messages.metadata.prompt_version` каждого ответа. Файлы версионируются
git; тесты — `backend/tests/test_prompts.py`.

---

## 2. Сборка запроса

```
[system] системный промпт уровня
[user]   … история диалога (последние 20 сообщений, ≤4000 символов каждое) …
[user]   текущий вопрос ученика
```

- История исключает текущий вопрос (он добавляется отдельно, без дублирования).
- Длинные сообщения обрезаются по 4000 символов.
- В модель уходит только текст: без user_id, email и метаданных.

## 3. Ключевые требования к ответам

### Базовый

1. Не давать готовый код решения.
2. Задавать наводящие вопросы.
3. Указывать место ошибки, но не исправлять.
4. Поощрять, объяснять через аналогии.
5. При третьей неудаче — упростить и привести пример на других данных.

### Средний

1. Назвать конкретную причину ошибки.
2. Показать правильный синтаксис (2–5 строк).
3. Сравнить «как было» / «как правильно».
4. Предложить мини-упражнение.
5. Не выдавать полное решение исходной задачи.

### Продвинутый

1. Полное решение.
2. Комментарии к значимым строкам.
3. Альтернативный подход + сравнение.
4. Стиль: PEP 8, имена, докстринги, краевые случаи.
5. Усложнение задачи.

## 4. Провайдеры

| `LLM_PROVIDER` | Класс | Примечание |
|----------------|-------|------------|
| `deepseek` | `DeepSeekProvider` | OpenAI-совместимый API, нужен `DEEPSEEK_API_KEY` |
| `lm_studio` | `LMStudioProvider` | локальный endpoint, ключ не проверяется |
| `echo` | `EchoProvider` | детерминированные ответы для e2e/демо, не для продакшена |

Настройки: `LLM_MAX_TOKENS` (2000), `LLM_TEMPERATURE` (0.7),
`LLM_FALLBACK_PROVIDER` (резервный провайдер, S12-002),
`LM_STUDIO_URL` и `LM_STUDIO_MODEL` (локальная модель, например
`qwen/qwen3-4b-2507`).

- **Healthcheck:** `GET /api/v1/health` → `llm.status` (`ok`, `degraded`,
  `not_configured`), кэш 60 с, ключ не раскрывается (S12-001).
- **Fallback:** при `LLMUnavailableError` — один повтор через резервный
  провайдер; если оба недоступны — 503 и понятное сообщение, а не пустой ответ.
- **Метрики:** каждый вызов пишется в память процесса (провайдер, модель,
  латентность, первый токен, токены, статус) и виден в
  `GET /api/v1/admin/analytics` → `llm.last_hour` / `llm.last_24h` (S12-003).
- **Политика уровня:** ответы `basic` с готовым кодом помечаются
  `warnings` (S12-005), но не блокируются.

**Живой прогон 2026-10-29 (DeepSeek):** basic 0.99, intermediate 0.93,
advanced 0.96 по рубрике; подробности — [LLM_EVAL.md](LLM_EVAL.md) §7 и
[reports/llm-eval/2026-10-29/](reports/llm-eval/2026-10-29/REVIEW.md).
Нарушение `intermediate/Q2` (полная программа) исправлено уточнением промпта
и версией v2.

## 5. Метрики ассистента

Часть метрик собирается автоматически (S12-003) и отдаётся в админку:

| Метрика | Источник | Целевое значение |
|---------|----------|------------------|
| Количество сообщений | `chat_messages` (аналитика) | — |
| Количество сессий | `chat_sessions` (аналитика) | — |
| Запросы к LLM | метрики в памяти | — |
| Ошибки провайдера | метрики в памяти | < 1% запросов |
| Латентность (avg/p95) | метрики в памяти | p95 < 5 с |
| Латентность первого токена | метрики в памяти | < 2 с |
| Токены (prompt/completion) | `usage` провайдера | ≤ 2000 на ответ |
| Срабатывания fallback | метрики в памяти | — |
| Нарушения политики `basic` | `metadata.warnings` | 0 (проверяется автоматически) |

Метрики живут в памяти процесса и обнуляются при рестарте — это осознанно:
отдельного хранилища (Prometheus/OTel) на этапе v0.2.0 нет.

Что **не** собирается автоматически: стоимость в деньгах (считать по токенам),
качество ответов по рубрике (только вручную по `LLM_EVAL.md`).

## 6. Правила изменения промптов

1. Правка — отдельный PR с префиксом `feat(prompts):` или `fix(prompts):`.
2. Обязателен прогон `pytest tests/test_prompts.py`.
3. Увеличить версию уровня в `prompts/versions.json` — она попадёт в метаданные
   новых ответов, по ней разбирают инциденты (текущая: intermediate = 2).
4. Ручная проверка на 5 типичных вопросах каждого уровня (см. LLM_EVAL).
5. Если меняется политика уровня — обновить [ASSISTANT_LEVELS.md](ASSISTANT_LEVELS.md).
6. Стоимость: не увеличивать `LLM_MAX_TOKENS` без согласования.
