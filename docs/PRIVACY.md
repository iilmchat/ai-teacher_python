# PRIVACY.md — персональные данные и их жизненный цикл (S26-004)

> Короткая политика для проекта «AI Teacher for Python» (v0.3.0). Технические
> детали — в SPEC §16, процедуры эксплуатации — в DESIGN_ADMIN_AND_OPS §11.

## 1. Какие данные храним

| Данные | Где | Зачем | Срок |
|--------|-----|-------|------|
| Email, username, хэш пароля (bcrypt), роль, уровень | `users` | вход, роли, уровень помощи | пока аккаунт активен |
| Прогресс по задачам (статус, попытки, дата завершения) | `user_task_progress` | обучение, отчёты учителя | пока аккаунт активен |
| Сессии и сообщения чата | `chat_sessions`, `chat_messages` | история помощи ученику | `RETENTION_CHAT_MESSAGES_DAYS` (90) |
| Запуски кода (код, вывод, ошибка) | `code_executions` | история песочницы | `RETENTION_CODE_EXECUTIONS_DAYS` (90) |
| Уведомления и достижения | `notifications`, `user_achievements` | мотивация | `RETENTION_NOTIFICATIONS_DAYS` (180) |
| Журнал действий teacher/admin | `audit_log` | безопасность, разбор инцидентов | `RETENTION_AUDIT_LOG_DAYS` (365) |

Пароли хранятся только как bcrypt-хэш; токены — JWT без ПДн (только `sub`).
Тексты решений и сообщений чата не используются для обучения моделей.

## 2. Кто имеет доступ

- ученик — свои данные (прогресс, чат, код);
- teacher — данные учеников своих классов (прогресс, отчёты);
- admin — управление пользователями/задачами, аналитика и журнал аудита;
- экспорт аналитики — только admin, каждое скачивание пишется в `audit_log`.

## 3. Экспорт

`GET /api/v1/admin/analytics/export?dataset=users|tasks|attempts|activity&format=csv|json`
— только администратор, потоково, лимит `EXPORT_MAX_ROWS` (100 000 строк).
`GET /api/v1/classrooms/{id}/report` — отчёт класса (CSV) для владельца класса.
Каждый экспорт фиксируется в журнале (`analytics.exported`,
`classroom.report_exported`).

## 4. Retention (сроки хранения)

`backend/scripts/apply_retention.py` удаляет записи старше настроенных сроков:
`--dry-run` показывает объём, обычный запуск удаляет батчами (по 1000).
Значение `0` отключает очистку для таблицы. Рекомендуемый запуск — cron раз в
сутки (пример в DESIGN_ADMIN_AND_OPS §11). Аудит хранится дольше остальных
данных (365 дней) — для разбора инцидентов.

## 5. Удаление аккаунта

`DELETE /api/v1/auth/me` с подтверждением паролем. Что происходит:

1. username/email заменяются заглушками (`deleted_<id>@invalid`);
2. хэш пароля заменяется случайным — вход невозможен;
3. аккаунт помечается `is_active=false`, токены перестают действовать;
4. прогресс/история остаются обезличенными (связь только по `user_id`);
5. событие `user.self_deleted` пишется в аудит.

Действие **необратимо**. Физическая чистка строк (hard delete) выполняется
вручную администратором при наличии правового требования — каскады БД удалят
связанные записи (см. ondelete в моделях).

## 6. Права пользователя

- узнать свои данные: `GET /api/v1/auth/me`, `GET /api/v1/me/*`;
- исправить: `PATCH /api/v1/auth/me`;
- удалить: `DELETE /api/v1/auth/me` (см. выше);
- экспорт своих данных: запрос администратору (dataset `users`/`attempts`
  фильтруется вручную до внедрения self-service экспорта).
