# PRIVACY.md — персональные данные и их жизненный цикл (S26-004, обновлено v0.5.0)

> Короткая политика для проекта «AI Teacher for Python» (v0.5.0). Технические
> детали — в SPEC §16, процедуры эксплуатации — в DESIGN_ADMIN_AND_OPS §11–14.

## 1. Какие данные храним

| Данные | Где | Зачем | Срок |
|--------|-----|-------|------|
| Email, username, хэш пароля (bcrypt), роль, уровень | `users` | вход, роли, уровень помощи | пока аккаунт активен |
| Прогресс по задачам (статус, попытки, дата завершения) | `user_task_progress` | обучение, отчёты учителя | пока аккаунт активен |
| Черновик решения: незавершённый код (S42-003) | `user_task_progress.draft_code` | восстановление работы после перезагрузки | пока аккаунт активен |
| История попыток: код решения, результат по тест-кейсам, время (S42-002) | `task_attempts` | обучение, разбор ошибок учеником | `RETENTION_TASK_ATTEMPTS_DAYS` (90) |
| Комментарии учителя к попыткам (S46-002) | `attempt_feedback` | обратная связь и разбор | вместе с попыткой (`RETENTION_TASK_ATTEMPTS_DAYS`) |
| Оценки ответов ассистента: 👍/👎 и комментарий ученика (S43-003) | `message_feedback` | качество ответов LLM; разбор негативных оценок админом | пока существует сообщение; выгрузка — по `EXPORT_MAX_ROWS` |
| Настройки профиля: язык, e-mail- и deadline-уведомления, шаблон промпта, сниппеты кода (S43-004, S44-003, S45-004) | `users.settings` JSONB | персонализация и удобство | пока аккаунт активен |
| Объявления класса (S46-006) | `classroom_announcements` | информирование учеников класса | пока существует класс |
| Сессии и сообщения чата | `chat_sessions`, `chat_messages` | история помощи ученику | `RETENTION_CHAT_MESSAGES_DAYS` (90) |
| Запуски кода (код, вывод, ошибка) | `code_executions` | история песочницы | `RETENTION_CODE_EXECUTIONS_DAYS` (90) |
| Уведомления и достижения | `notifications`, `user_achievements` | мотивация | `RETENTION_NOTIFICATIONS_DAYS` (180) |
| Активные сессии: `jti`, user-agent, IP входа (S45-005) | `user_sessions` | список устройств и отзыв доступа | пока сессия не отозвана/не истекла |
| Журнал действий teacher/admin | `audit_log` | безопасность, разбор инцидентов | `RETENTION_AUDIT_LOG_DAYS` (365) |

Пароли хранятся только как bcrypt-хэш; токены — JWT без ПДн (только `sub`).
Тексты решений и сообщений чата не используются для обучения моделей.

## 2. Кто имеет доступ

- ученик — свои данные (прогресс, чат, код, комментарии учителей, свои оценки
  ответов и настройки);
- teacher — данные учеников своих классов (прогресс, работы и код,
  комментарии, отчёты; только владелец класса);
- admin — управление пользователями/задачами, аналитика, журнал аудита и
  сводка качества LLM; тексты оценок и комментариев учеников видны только в
  этой сводке/выгрузке негативных оценок;
- экспорт аналитики и негативных оценок — только admin, каждое скачивание
  пишется в `audit_log`.

## 3. Экспорт

`GET /api/v1/admin/analytics/export?dataset=users|tasks|attempts|activity&format=csv|json`
— только администратор, потоково, лимит `EXPORT_MAX_ROWS` (100 000 строк).
`GET /api/v1/admin/quality/export?format=csv|json` — только администратор,
негативные оценки ассистента с комментариями (вход для LLM-разбора).
`GET /api/v1/classrooms/{id}/report` — отчёт класса (CSV) для владельца класса.
Каждый экспорт фиксируется в журнале (`analytics.exported`,
`quality.exported`, `classroom.report_exported`).

**Выгрузка своих данных (S45-003, дополнено v0.5.0).**
`GET /api/v1/users/me/export` — JSON-файл со всеми данными пользователя:
профиль и настройки, прогресс (включая черновик), попытки, комментарии
учителей к попыткам, сессии чата с сообщениями, собственные оценки ответов
ассистента, уведомления и достижения. В файл не входят эмбеддинги сообщений,
хэш пароля и данные других пользователей (для комментариев сохраняется только
имя учителя, которое ученик и так видит в интерфейсе). Файл отдаётся как вложение
(`ai-teacher-export-<дата>.json`) и после скачивания живёт только на
устройстве пользователя — сервер его не сохраняет. Каждая выгрузка пишется
в журнал (`user.data_exported`).

## 4. Retention (сроки хранения)

Retention применяет само приложение (встроенный планировщик, KI-025) или скрипт
`backend/scripts/apply_retention.py`: записи старше настроенных сроков удаляются
батчами (по 1000), `--dry-run` показывает объём. Значение `0` отключает очистку
для таблицы.

Встроенный планировщик включается `RETENTION_SCHEDULER_ENABLED` (в production —
из `docker-compose.prod.yml`), запускается раз в сутки в `RETENTION_SCHEDULER_AT`
(UTC) и не выполняется дважды при нескольких инстансах (advisory-lock
PostgreSQL). Альтернатива — внешний cron (пример в DESIGN_ADMIN_AND_OPS §11).
Аудит хранится дольше остальных данных (365 дней) — для разбора инцидентов.

## 5. Удаление аккаунта

`DELETE /api/v1/auth/me` с подтверждением паролем. Что происходит:

1. username/email заменяются заглушками (`deleted_<id>@invalid`);
2. хэш пароля заменяется случайным — вход невозможен;
3. аккаунт помечается `is_active=false`, токены перестают действовать;
4. прогресс/история остаются обезличенными (связь только по `user_id`);
5. событие `user.self_deleted` пишется в аудит.

Действие **необратимо**. Физическая чистка строк (hard delete) выполняется
вручную администратором при наличии правового требования — каскады БД удалят
связанные записи (см. ondelete в моделях).

## 6. Права пользователя

- узнать свои данные: `GET /api/v1/auth/me`, `GET /api/v1/me/*`;
- исправить: `PATCH /api/v1/auth/me`;
- удалить: `DELETE /api/v1/auth/me` (см. выше);
- выгрузить свои данные: `GET /api/v1/users/me/export` (JSON-файл, S45-003);
- сменить пароль: `POST /api/v1/users/me/password` (S45-001);
- увидеть и отозвать активные сессии: `GET /api/v1/users/me/sessions`,
  `DELETE /api/v1/users/me/sessions/{id}`,
  `POST /api/v1/users/me/sessions/revoke-others` (S45-005).

## 7. Мониторинг и Sentry (S35)

- **Метрики Prometheus** (`/metrics`) не содержат ПДн: только агрегаты по
  путям, провайдерам, статусам и режимам. Эндпоинт доступен только внутренней
  сети (nginx отдаёт 404).
- **Логи** структурированные; email в сообщениях маскируется
  (`mask_email`), токены и тела запросов не логируются.
- **Sentry** (backend и frontend) используется только для технических ошибок.
  Политика: `send_default_pii=False`, тела запросов не отправляются,
  `before_send` вычищает email, username, IP, токены, тексты кода и промптов;
  в сообщениях email/IP маскируются (`<email>`, `<ip>`). Пользователь
  идентифицируется только внутренним `id` (без email/логина/IP).
- Основание обработки — обеспечение безопасности и работоспособности сервиса
  (законный интерес); данные Sentry хранятся во внешнем SaaS и не используются
  для обучения моделей.
- Отключение: пустой `SENTRY_DSN` (Sentry не инициализируется).
