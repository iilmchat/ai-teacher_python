# Шаг 05 / спринт 43: код между чатом и песочницей

**Дата:** 2026-11-06  
**Спринт:** 43 (v0.5.0 «Learning Experience & Teaching Workflow»)  
**Задача:** S43-005 — код из чата в песочницу  
**Статус:** реализовано

---

## 1. Что сделано

1. **«В песочницу» у блока кода.** В шапке каждого блока кода в ответе
   ассистента появилась кнопка: код уходит в редактор песочницы.
2. **Передача через два слота в localStorage**
   (`frontend/src/lib/codeTransfer.ts`): `incoming` — код, переданный из
   другой страницы (песочница забирает его один раз), `draft` — код, с
   которым работает ученик. Слоты разведены намеренно: переданный код не
   должен молча затирать черновик.
3. **Подтверждение замены.** Если в песочнице уже есть код и он отличается от
   переданного, показывается вопрос «В песочницу пришёл другой код. Заменить
   текущий?» с вариантами «Заменить» и «Оставить текущий».
4. **Черновик песочницы сохраняется.** Код в редакторе пишется в localStorage
   при каждом изменении и восстанавливается при следующем визите.
5. **Обратный сценарий «Спросить ассистента».** Кнопка в песочнице уводит в
   чат, где текущий код подставляется в поле ввода **вложением** (блоком
   кода) — не как «решение задачи».
6. **Автоотправки нет ни в одну сторону.** Код ждёт в поле ввода, пока
   ученик не нажмёт «Отправить». Если чата ещё нет, он создаётся — это
   следствие явного действия ученика, а не отправка сообщения.
7. **Управляемый ввод.** `MessageInput` переведён на контролируемый вид
   (`value` + `onChange`): иначе код из песочницы нельзя положить в поле.

## 4. Проблемы и отклонения

- **Без подтверждения чужой черновик затирался бы.** Прямая запись в слот
  черновика из чата ломала бы работу ученика (потерянный код). Поэтому
  передача идёт отдельным слотом, а решение принимает песочница.
- **Поле ввода пришлось сделать управляемым.** Раньше текст жил внутри
  `MessageInput`, и код из песочницы некуда было положить. `MessageInput`
  переведён на `value`/`onChange` — это изменение затронуло и его тесты.
- **Чата может не быть.** Если ученик пришёл из песочницы, а чат не открыт,
  поле ввода не отрисовывается. Поэтому при переходе из песочницы создаётся
  сессия: это следствие явного действия ученика («Спросить ассистента»), а не
  автоотправка. Сообщение при этом не отправляется.
- **Код не уходит на сервер.** Передача — между страницами браузера; ни в
  БД, ни в API код не попадает. Поэтому `docs/PRIVACY.md` не менялся.
- **Локальный e2e после обновления esbuild требует обхода**
  (`ESBUILD_BINARY_PATH`): бинарник из pnpm-стора на Windows не может
  создавать файлы — так же, как в CI-скрипте `scripts/ci/e2e.ps1`.

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| Передавать код через API или между страницами | **Между страницами (localStorage)** | Код не должен покидать браузер: в API он попал бы в историю чата и в логи. |
| Один слот в localStorage или два | **Два (`incoming` и `draft`)** | Иначе переданный код затирает черновик без вопроса ученику. |
| Спрашивать перед заменой или заменять молча | **Спрашивать** | Чужой черновик — работа ученика; терять её без подтверждения нельзя. |
| Отправлять код в чат сразу или подставлять в поле | **Подставлять в поле** | Решение «спросить ассистента» и есть действие ученика; автоотправка лишила бы его контроля над текстом вопроса. |
| Код вложением или отдельным сообщением | **Вложением в текст сообщения** | Вложение видно в том же сообщении, которое ученик может дописать своим текстом. |
| Хранить черновик песочницы или нет | **Хранить** | Раньше код песочницы терялся при уходе со страницы — это отдельная потеря, не связанная с S43-005. |
| Создавать сессию чата автоматически при переходе из песочницы | **Да** | Без чата нет поля ввода, и код некуда положить; сообщение при этом не отправляется. |
