**Дата:** 2026-11-06

**Задача:** S44-001 — stdin, лимиты и анализ в UI  
**Статус:** реализовано

---

## 1. Что сделано

1. **Поле «Ввод (stdin)» под редактором.** Данные для `input()` вводятся
   в `CodePage` и уходят в `POST /code/execute` вместе с кодом. Подсказка
   объясняет формат: одна строка на вызов. Пустое поле означает, что ввод
   не передаётся.
2. **Проброс stdin проверен на backend.** Тест `test_execute_forwards_stdin_to_executor`
   фиксирует, что API передаёт строку в исполнитель без изменений.
3. **Блок «Ограничения песочницы».** Раскрывающаяся секция получает данные
   из `GET /code/limits`: таймаут, память, длина кода, лимит вывода и
   разрешённые модули. Пока ответа нет — загрузка; при ошибке — сообщение,
   но редактор и запуск продолжают работать.
4. **Блок «Разбор кода».** Кнопка «Разобрать» вызывает `POST /code/analyze`
   и показывает сводку, метрики (`lines`, `functions`, `classes`, `loops`,
   `conditions`, `imports`) и замечания, сгруппированные по важности:
   ошибки, предупреждения, подсказки.
5. **Типы и i18n.** В `types/api.ts` добавлены `SandboxLimits` и
   `AnalyzeResponse`; новые строки заведены в `ru.json` и `en.json`.

## 4. Проблемы и отклонения

- **Локальное окружение отставало от `main`.** В `backend/venv` стояли
  ruff 0.8.1 и mypy 1.13, которые не понимали правила `UP046` и
  per-module `disable_error_code`; инструменты обновлены до ruff 0.17 и
  mypy 2.4, как в CI. Зависимости backend синхронизированы с
  `requirements.txt`.
- **Полный backend-прогон не завершился по инфраструктурной причине.**
  Docker Desktop на машине остановился, Postgres на `127.0.0.1:5434` перестал
  отвечать; тесты, которым нужна БД, упали на фикстуре подключения. Это не
  связано с изменениями шага: целевой `test_code_api.py` прошёл (11 passed),
  а полный прогон повторит CI.
- **E2E в этом шаге не добавлялся.** Требование шага — юнит-тесты; сквозной
  сценарий «код → stdin → вывод → история» станет частью DoD спринта после
  S44-002, когда появится история запусков.
- **Клиентское ограничение длины stdin не вводилось.** Сервер уже
  ограничивает stdin 10 000 символов; общие клиентские лимиты — задача
  S44-003.

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| Ввод stdin через диалог/консоль или отдельное поле | **Отдельное поле** | В песочнице нет интерактивной консоли; поле показывает, какие данные получит `input()`. |
| Хранить лимиты в frontend или брать из API | **Из `GET /code/limits`** | Числа должны совпадать с тем, что реально применяет сервер; дублирование разъедется. |
| Разбирать код автоматически при каждом запуске или по кнопке | **По кнопке** | Разбор — отдельное действие: не тратит запрос, не мешает запуску и оставляет решение ученику. |
| Показывать замечания одним списком или по важности | **По важности** | Ошибки, предупреждения и подсказки имеют разный вес; ученику проще начать с критичного. |
