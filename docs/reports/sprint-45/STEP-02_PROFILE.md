# Шаг 02 / спринт 45: профиль, e-mail и удаление аккаунта

**Дата:** 2026-11-07  
**Спринт:** 45 (v0.5.0 «Learning Experience & Teaching Workflow»)  
**Задача:** S45-002 — правка профиля и удаление аккаунта из UI  
**Статус:** реализовано

---

## 1. Что сделано

1. **Уведомление на старый e-mail.** `email.py` получил
   `send_email_change_email`: при реальной смене адреса владельцу уходит
   письмо на прежний адрес (best-effort). `PATCH /auth/me` вызывает его через
   `_notify_email_change`; сбой SMTP пишется warning'ом и не ломает запрос.
2. **Карточка «Данные аккаунта».** Поля e-mail и имени предзаполнены
   профилем; сохранение — `PATCH /auth/me`, кнопка «Отменить правки»
   возвращает значения. Серверные ошибки (занятый e-mail/имя) показываются
   как есть.
3. **Карточка «Опасная зона».** Модальное окно с паролем и предупреждением о
   необратимости (`DELETE /auth/me`). Локальная сессия очищается только после
   успешного удаления: при неверном пароле аккаунт остаётся живым.
4. **`api.delete` с телом.** Клиент расширен необязательным `body`, чтобы
   передавать пароль в DELETE (по контракту S26-004).
5. **Стор.** `updateProfile(data)` и `deleteAccount(password)`; последний
   вызывает `logout()` только при успехе.
6. **Тесты.** Backend — 8 тестов: правка e-mail/имени, занятый e-mail,
   уведомление на старый адрес, сбой SMTP, удаление с неверным паролем, без
   пароля, анонимизация с блокировкой входа и отзывом refresh. Frontend — 7
   тестов: предзаполнение и PATCH, недоступность кнопки без изменений,
   ошибка сервера, отмена правок, удаление аккаунта, сохранение сессии при
   неверном пароле, закрытие модального окна.

## 4. Проблемы и отклонения

- **Логин после удаления.** Найден баг: `deleteAccount` в первой версии
  разлогинивал в `finally`, то есть и при неверном пароле. Тест поймал
  ложный выход; logout перенесён после успешного DELETE.
- **Уведомление best-effort.** Если SMTP недоступен, смена e-mail всё равно
  происходит (требование шага): письмо — сигнал владельцу, а не блокировка.
- **Динамический импорт отправителя.** `get_email_sender` импортируется
  внутри функции, чтобы тест мог подменить его через
  `monkeypatch` на модуле `app.services.email`.

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| Отдельные endpoint'ы для e-mail и имени или существующий PATCH | **PATCH /auth/me** | Контракт уже есть, уникальность проверяет сервер. |
| Писать письмо на новый адрес | **На старый** | Владелец должен узнать о смене даже при чужом доступе. |
| Разлогинивать при любом исходе DELETE | **Только при успехе** | Иначе неверный пароль выкидывает из живого аккаунта. |
| Отдельная страница удаления | **Модальное окно** | Меньше кликов, предупреждение рядом с кнопкой. |
