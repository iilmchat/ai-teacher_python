**Статус:** реализовано

## 1. Что сделано

1. **Сервис `personal_export.py`.** `collect_user_data(db, user)` собирает
   один JSON: профиль, прогресс по задачам, попытки, сессии чата с
   сообщениями, уведомления и достижения. Каждая выборка фильтруется по
   `user_id`; сообщения — по сессиям пользователя.
2. **Служебные поля исключены.** Сообщение сериализуется без `embedding`
   (вектор семантического поиска), профиль — без `hashed_password`; в
   `metadata` остаётся то, что пользователь видел в ответе.
3. **`GET /users/me/export`.** Отдаёт JSON с `Content-Disposition:
   attachment; filename="ai-teacher-export-<дата>.json"`; пишет аудит
   `user.data_exported`. Требует авторизации — заблокированный аккаунт
   выгрузку не получит.
4. **UI.** Карточка «Мои данные»: пояснение, что файл содержит персональные
   данные и хранится локально, кнопка «Скачать мои данные» через
   `api.download` + `saveBlob`.
5. **Документация.** `PRIVACY.md` §1 (таблица данных) и §6 (права): выгрузка
   self-service, состав файла и срок жизни на стороне пользователя.
6. **Тесты.** Backend — 8: требование авторизации, JSON-вложение, разделы и
   профиль, чат без embedding и без чужих данных, попытки/прогресс,
   уведомления, отсутствие хэша пароля, аудит. Frontend — 2: скачивание и
   `saveBlob`, ошибка сети.

## 4. Проблемы и отклонения

- **Черновики входят в выгрузку.** `draft_code` и `best_solution` — данные
  пользователя, поэтому включены; это согласуется с PRIVACY.md.
- **Файл формируется в памяти.** Отдельного стриминга нет: объём ограничен
  лимитами чата и попыток одного ученика. При росте данных можно перейти на
  потоковую отдачу, как в админском экспорте.
- **Имя файла на клиенте** строится из локальной даты (серверный
  `Content-Disposition` клиент не читает) — формат совпадает.

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| Переиспользовать админский `export_service` | **Отдельный сервис** | Там наборы «вся таблица», а здесь — один пользователь и вложенные сущности. |
| Выгружать embedding | **Нет** | Это служебный вектор, а не данные пользователя; файл и без него большой. |
| CSV или JSON | **JSON** | Вложенные чаты/попытки и разнородные разделы естественны в JSON. |
| Стриминг | **Один документ** | Проще и достаточно для объёма одного аккаунта. |
