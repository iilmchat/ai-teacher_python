**Дата:** 2026-11-08
**Спринт:** 46 (v0.5.0 «Learning Experience & Teaching Workflow»)
**Задача:** S46-004 — перенос срока и снятие назначения
**Статус:** реализовано

---

## 1. Что сделано

1. **`PATCH /classrooms/{id}/assignments/{assignment_id}`** — перенос срока
   (`due_at`, можно очистить). Доступ только владельцу класса; чужой
   учитель получает 403, неизвестное назначение — 404. Действие пишется в
   аудит (`assignment.updated`).
2. **`DELETE /classrooms/{id}/assignments/{assignment_id}`** — снятие
   назначения. Доступ только владельцу. Уведомления о назначении удаляются
   (`Notification.type="assignment"` с этим `assignment_id`), прогресс
   учеников (`UserTaskProgress`) не трогается. Аудит — `assignment.deleted`.
3. **Идемпотентность.** Повторное снятие возвращает 204: назначения уже нет,
   ошибки для клиента нет. `PATCH` по исчезнувшему назначению — 404.
4. **UI.** В строке назначения появились:
   - поле даты и кнопка «Сохранить срок»;
   - «Снять» с двухшаговым подтверждением («Точно снять?» / «Отмена»);
   - чекбоксы и панель массового переноса срока для выбранных назначений.
5. **Тесты.** Backend — 6 (перенос, права, сохранение прогресса, отмена
   уведомлений, идемпотентность, 404). Frontend — 3 (перенос из строки,
   снятие с подтверждением, массовый перенос).

## 4. Проблемы и отклонения

- **Массовый перенос — цикл PATCH'ей.** Отдельный bulk-эндпоинт не нужен:
  назначений в классе десятки, а не тысячи. При ошибке на одном из шагов
  показывается ошибка, уже перенесённые остаются перенесёнными.
- **Снятие не удаляет прогресс.** Это требование шага: ученик мог решить
  задачу, и его результат должен остаться в истории и статистике.
- **Уведомления отменяются только по назначению.** Deadline-уведомления
  живут отдельно и исчезнут сами, когда пропадёт назначение.

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| `PATCH` только `due_at` | **Да** | Смена задачи — это снятие + новое назначение; частичное редактирование не нужно. |
| DELETE идемпотентен | **Да** | Повторный клик/retry не должен пугать учителя ошибкой. |
| Двухшаговое подтверждение | **Да** | Без `window.confirm`: работает в e2e и доступно с клавиатуры. |
| Чекбоксы для массового переноса | **Да** | Одна панель, без отдельного экрана. |
