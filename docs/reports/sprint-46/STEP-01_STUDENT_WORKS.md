# Шаг 01 / спринт 46: просмотр и разбор работ ученика

**Дата:** 2026-11-08
**Спринт:** 46 (v0.5.0 «Learning Experience & Teaching Workflow»)
**Задача:** S46-001 — работы ученика для учителя и `best_solution`
**Статус:** реализовано

---

## 1. Что сделано

1. **`GET /teacher/students/{student_id}/attempts`.** Список попыток ученика
   с названием задачи, счётом и временем, новые сверху; фильтр `task_id`,
   пагинация `skip`/`limit`. Доступ — только владельцу класса, в котором
   состоит ученик; администратор не ограничен классами.
2. **`GET /teacher/students/{student_id}/attempts/{attempt_id}`.** Детальная
   работа: код, разбор по тест-кейсам, время. Попытка обязана принадлежать
   этому ученику — иначе 404, как в ученическом API.
3. **Права в одном месте.** `TeacherService.get_student_for_teacher`:
   несуществующий/не-ученик — 404, чужой ученик (не в классах учителя) — 403.
4. **`best_solution` больше не «мёртвое» поле.** `TeacherProgressItem`
   отдаёт последнее успешное решение завершённой задачи; в карточке прогресса
   оно раскрывается под строкой задачи. `KI-029` закрыт.
5. **UI.** В карточке ученика появились вкладки «Прогресс» и «Работы»:
   список попыток, открытие работы с read-only-редактором (подсветка в
   обычном режиме, textarea в e2e) и таблицей «ожидалось/получено».
6. **Тесты.** Backend — 6: список, деталь, чужой учитель (403), неизвестный
   ученик (404), администратор, `best_solution`. Frontend — 4: список работ,
   деталь с кодом, ошибка загрузки, показ решения.

## 4. Проблемы и отклонения

- **Доступ по классу, а не по назначению.** Учитель видит попытку, если
  ученик состоит в его классе, даже если задача назначалась другим классом.
  Это соответствует формулировке шага и не раскрывает работы учеников,
  которых у учителя нет.
- **`best_solution` отдаётся только для завершённых задач.** Для задачи в
  процессе последнее успешное решение не существует; пустое значение честнее
  старого кода.
- **Редактор read-only.** Переиспользован `CodeEditor` с `readOnly`: в
  обычном режиме — Monaco с подсветкой, в e2e — textarea (как во всём
  проекте).

## 5. Обоснование решений

| Вариант | Выбран | Почему |
|---------|--------|--------|
| Проверять назначение задачи | **Членство в классе** | Учитель должен разбирать любые работы своих учеников, не только назначенные им. |
| Отдельный сервис `TeacherService` | **Да** | Правила доступа переиспользуются комментариями (S46-002) и не раздувают `ClassroomService`. |
| Отдавать код в списке попыток | **Только в детали** | Список остаётся лёгким, код грузится по клику. |
| `best_solution` как отдельный endpoint | **Поле прогресса** | Карточка уже загружается одним запросом; лишний round-trip не нужен. |
