## 4. Smoke

1. Учитель создаёт класс → получает 6-символьный код; ученик вступает по коду
   (регистр не важен), класс виден обоим.
2. Учитель назначает задачу с дедлайном; ученик видит её на `/assignments`,
   просроченная помечена «просрочено».
3. Ученик решает задачу → в матрице класса ✓ и число попыток,
   `completion_rate` растёт.
4. Повторное назначение той же задачи → 409; чужой класс → 403.
5. Владелец исключает ученика; себя удалить нельзя (400).
6. `alembic downgrade 006 && upgrade head` — чисто.

## 5. Что не так

- Прогресс класса видит только владелец; участник получает 403 (осознанно).
- Назначение — по одной задаче за запрос; массовое назначение не сделано.
- Уведомлений о новых заданиях нет — спринт 17.
- Список классов без пагинации (у учителя их обычно немного).
- CI не стартовал (KI-014, биллинг); мерж по временному разрешению.

## 7. Обоснование

- **Владелец — участник с ролью `owner`.** Одна таблица участников вместо
  отдельного поля membership; проверки членства и роли — в одном месте.
- **6-символьный код без похожих символов.** Алфавит без `O/0`, `I/1`;
  коллизии проверяются при генерации, код уникален.
- **Назначение уникально по (класс, задача).** Дубликат — 409, а не тихое
  дублирование в матрице.
- **Матрица строится одним срезом прогресса.** Прогресс всех учеников по
  назначенным задачам читается одним запросом, а не N×M.
- **`/me/assignments` — отдельный взгляд ученика.** Дедлайны и `overdue`
  вычисляются на сервере, UI только отображает.
