# Сумма чисел до N — разбор с экспертной точки зрения

## Краткий разбор проблемы

На первый взгляд задача тривиальна: сложить числа от 1 до N. Но именно такие задачи — отличный полигон, чтобы разобрать **типы, краевые случаи, сложность и идиоматичность**. Ключевые вопросы: что считать «числами до N» (1..N или 0..N?), что делать при N ≤ 0, при нецелых N, при огромных N (переполнение — не проблема в Python, но производительность — да). Правильное решение — функция с явным контрактом, валидацией и выбором алгоритма под задачу.

## Полное решение

```python
"""Сумма целых чисел от 1 до N включительно."""

from __future__ import annotations  # единый стиль аннотаций (PEP 563)


def sum_upto(n: int) -> int:
    """Вернуть сумму 1 + 2 + ... + n.

    Для n <= 0 возвращает 0 (сумма пустого диапазона).
    Сложность O(1) по формуле Гаусса.

    Args:
        n: верхняя граница, целое число.

    Returns:
        Сумма целых от 1 до n.

    Raises:
        TypeError: если n не является int (bool тоже отсекается).
    """
    # bool — подкласс int в Python; True/False лучше явно отвергнуть,
    # чтобы не получить неожиданно sum_upto(True) == 1.
    if isinstance(n, bool) or not isinstance(n, int):
        raise TypeError(f"n должно быть int, получено {type(n).__name__}")

    if n <= 0:
        return 0  # краевой случай: пустая сумма

    # Формула Гаусса: n*(n+1)/2. В Python // даёт точное целое.
    return n * (n + 1) // 2


if __name__ == "__main__":
    # Простой CLI: читаем N из argv, аккуратно обрабатываем ошибки ввода.
    import sys

    if len(sys.argv) != 2:
        print("Использование: python sum_upto.py N")
        sys.exit(1)

    try:
        n = int(sys.argv[1])
    except ValueError:
        print(f"Ожидалось целое число, получено: {sys.argv[1]!r}")
        sys.exit(2)

    print(sum_upto(n))
```

## Пояснения

1. **Формула Гаусса вместо цикла.** `n*(n+1)//2` — это **O(1)** по времени и памяти против **O(n)** у цикла. При N = 10⁹ разница — секунды против наносекунд. `//` (целочисленное деление) корректен, потому что произведение двух последовательных чисел всегда чётно.
2. **Явная валидация типа.** `isinstance(n, bool)` перед `isinstance(n, int)` — потому что `bool` наследуется от `int`. Без этой проверки `sum_upto(True)` вернёт `1` — тихая ошибка, которую трудно поймать.
3. **Краевой случай N ≤ 0.** Возвращаем `0`, а не бросаем исключение: сумма пустого множества по соглашению равна нулю (как `sum([])`). Это делает функцию композируемой.
4. **Докстринг в стиле Google** — стандарт для читаемости и автогенерации документации (Sphinx, pdoc).
5. **`from __future__ import annotations`** — полезно, если позже захочется писать `int | None` в аннотациях на старых версиях Python (3.7–3.9).

## Альтернативный вариант (цикл) и сравнение

```python
def sum_upto_loop(n: int) -> int:
    """Сумма 1..n через цикл. Сложность O(n)."""
    if not isinstance(n, int) or isinstance(n, bool):
        raise TypeError("n должно быть int")
    total = 0
    for i in range(1, n + 1):  # range(1, n+1) даёт 1, 2, ..., n
        total += i
    return total
```

Или ещё короче, «питонично»:

```python
def sum_upto_builtin(n: int) -> int:
    return sum(range(1, n + 1))  # тот же O(n), но в C-цикле
```

**Сравнение:**

| Вариант | Сложность | Плюсы | Минусы |
|---|---|---|---|
| Формула | O(1) | Мгновенно при любом N | Требует математики; не обобщается на «сумму квадратов» тривиально |
| `for`-цикл | O(n) | Понятен новичку | Медленно на больших N, многословно |
| `sum(range(...))` | O(n) | Идиоматично, быстро за счёт C | Всё равно линейно; `range` строит объект (лениво, но итерация реальна) |

**Когда что выбирать:** формула — если задача именно «сумма арифметической прогрессии». Цикл/`sum(range(...))` — если нужна обобщаемость (например, фильтр по условию: `sum(x for x in range(1, n+1) if x % 3 == 0)`).

## Усложнение задачи

1. **Сумма только чётных / кратных k** до N: `sum(x for x in range(1, n+1) if x % k == 0)`. Попробуй вывести **замкнутую формулу** через `k * m*(m+1)//2`, где `m = n // k`.
2. **Сумма цифр всех чисел от 1 до N** — уже нетривиально, требует цифрового DP или разбора по разрядам. Отличное упражнение на рекурсию.
3. **Сумма квадратов / кубов 1..N** — выведи формулы `n(n+1)(2n+1)/6` и `[n(n+1)/2]²` и сравни с циклом.
4. **Беззнаковый ввод из файла** с миллионами N — замерь время формулы vs цикла через `timeit`.

## Потенциальные ошибки на будущее

- **`range(n)` vs `range(1, n+1)`** — классическая ошибка «на единицу». Всегда проверяй на `n=1` (должно быть `1`) и `n=0` (должно быть `0`).
- **`bool` как `int`** — если не отсекать, `sum_upto(True)` тихо вернёт `1`, а `sum_upto(False)` — `0`. В продакшене такие баги живут годами.
- **`float` вместо `int`** — `sum_upto(5.0)` в наивном цикле сработает (`range` не примет, упадёт), а в формуле даст `15.0` (float). Явная проверка типа убирает неоднозначность.
- **Огромный N в цикле** — при N = 10⁹ цикл «повиснет» на минуты. Формула — страховка.
- **Переполнение** — в Python его нет (big int), но в C/Java/Go формула `n*(n+1)/2` для `int32` переполнится при N > ~65535. Если портируешь — используй 64-бит или проверяй границы.
