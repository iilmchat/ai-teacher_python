# advanced · Q3

**Вопрос:** Код: `while i < 10: print(i)` — зависает

**Провайдер:** deepseek (deepseek-chat) · **Версия промпта:** 1

**Предупреждения политики:** нет

## Ответ

## Краткий разбор проблемы

Бесконечный цикл: в теле `while` переменная `i` не изменяется, поэтому условие `i < 10` всегда истинно (при `i < 10` на входе). Кроме того, `i` вообще не определена — при первом же проходе получите `NameError`, если не задать её до цикла. Классическая ошибка «забыл инкремент». Правильный подход — либо явный счётчик с инкрементом, либо идиоматичный `for i in range(10)`.

## Полное решение с комментариями

```python
def print_numbers(limit: int = 10) -> None:
    """Печатает целые числа от 0 до limit-1 включительно.

    Args:
        limit: верхняя граница (не включается). Должна быть >= 0.

    Raises:
        ValueError: если limit отрицательный.
    """
    if limit < 0:
        # Явный контракт: отрицательный предел — ошибка вызывающего кода,
        # а не тихий пустой вывод. Это лучше, чем молча проглотить баг.
        raise ValueError(f"limit must be >= 0, got {limit}")

    i = 0                       # инициализация ДО цикла — иначе NameError
    while i < limit:            # условие проверяется на каждом шаге
        print(i)                # тело цикла
        i += 1                  # инкремент — без него цикл бесконечный


if __name__ == "__main__":
    print_numbers()
```

Ключевые моменты:
- `i = 0` до цикла — иначе `NameError`.
- `i += 1` в конце тела — гарантирует продвижение к выходу.
- `limit: int` и проверка `< 0` — защита от «тихого» пустого вывода при отрицательном аргументе (частая ловушка).
- `if __name__ == "__main__":` — идиома: код не выполнится при импорте модуля.

## Пояснения

1. **Почему зависало.** В `while` условие пересчитывается перед каждой итерацией. Без изменения `i` оно навсегда остаётся `True`. Это не баг Python, а логическая ошибка — интерпретатор делает ровно то, что написано.
2. **`NameError` vs `UnboundLocalError`.** Если `i` не определена вообще — `NameError`. Если она присваивается где-то внутри функции ниже цикла — `UnboundLocalError`. Обе — следствие отсутствия инициализации.
3. **Сложность.** O(n) по времени, O(1) по памяти. `range` в `for` — тоже O(1) по памяти (ленивый), в отличие от `list(range(n))`.
4. **Идиоматичность.** В Python `while` с ручным счётчиком — почти всегда «код с запахом». Для итерации по диапазону есть `for ... in range(...)`. `while` уместен, когда число итераций заранее неизвестно (чтение до EOF, поиск, ретраи).
5. **PEP 8.** Имена — `snake_case`, докстринг в тройных кавычках, отступы 4 пробела, аннотации типов для публичных функций. `print(i)` без `sep`/`end` — нормально для простого вывода.

## Альтернативный вариант и сравнение

```python
# Идиоматично: for + range — читается как «для i из 0..9»
for i in range(10):
    print(i)

# Если нужен именно while (например, i меняется нелинейно):
i = 0
while i < 10:
    print(i)
    i += 1
```

Сравнение:

| Критерий | `for i in range(10)` | `while i < 10: ... i += 1` |
|---|---|---|
| Читаемость | Максимальная: сразу виден диапазон | Нужно сканировать тело в поисках инкремента |
| Риск бесконечного цикла | Нулевой | Есть (забыл `i += 1`) |
| Гибкость условия | Только последовательность | Любое условие, нелинейный шаг |
| Производительность | `range` — C-уровень, чуть быстрее | Чуть медленнее из-за интерпретации условия |

**Вывод:** для «пройти по числам» — всегда `for`. `while` — когда условие выхода зависит от состояния (поиск, парсинг, ожидание).

## Усложнение задачи

1. **С шагом и границами.** Напишите `print_numbers(start: int, stop: int, step: int = 1)`, поддержите отрицательный `step` (обратный отсчёт), проверьте, что `step != 0` (`ValueError`).
2. **Без `range`.** Реализуйте ту же функцию на чистом `while`, но так, чтобы корректно работали и отрицательные `step` (условие `i < stop` для положительного шага и `i > stop` для отрицательного).
3. **Генератор.** Перепишите как `def numbers(limit): yield ...` — тогда память O(1) при любом `limit`, и можно писать `sum(numbers(10**9))`.
4. **Защита от зависания.** Добавьте «предохранитель»: если цикл сделал больше `N` итераций — `RuntimeError` (полезно в проде при работе с внешними данными).

## Потенциальные ошибки на будущее

- **Забытый инкремент** — главная причина. Правило: заходя в `while`, сразу спросите «что здесь меняет условие?».
- **`i` не инициализирована** — `NameError`. Инициализируйте до цикла, а не «где-то потом».
- **Изменение `i` внутри `if`** — если инкремент спрятан в ветке, при невыполнении условия цикл зависнет. Инкремент — на верхнем уровне тела.
- **Мутация коллекции во время итерации** (`while i < len(lst): lst.pop(...)`) — классический источник ошибок индексации. Используйте `for` по копии или собирайте новый список.
- **Типы.** `i = "0"` + `i += 1` → `TypeError`. Аннотации и проверки в начале функции ловят это раньше.
- **`while True` без `break`** — легитимная идиома для «цикла с выходом по условию», но убедитесь, что `break` достижим на всех путях.
