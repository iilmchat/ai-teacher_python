# Разбор `print(sum(range(10)))`

## Краткий разбор проблемы

Код **работает корректно** и выведет `45` — сумма чисел от 0 до 9. Но это, скорее, «однострочник для демонстрации», а не решение задачи: здесь нет ни постановки задачи, ни обработки краевых случаев, ни явного контракта. Как преподаватель я вижу типичную ловушку начинающих: **выражение без функции** — его нельзя переиспользовать, протестировать или адаптировать. Ниже — как превратить эту строку в идиоматичный, тестируемый код.

## Полное решение с комментариями

```python
"""Модуль для вычисления суммы натуральных чисел до заданной границы."""

from typing import Iterable


def sum_range(n: int, *, inclusive: bool = False) -> int:
    """Вернуть сумму целых чисел от 0 до n.

    Args:
        n: Верхняя граница (неотрицательное целое).
        inclusive: Если True — включать n в сумму (0..n),
                   иначе — 0..n-1 (поведение range(n)).

    Returns:
        Сумма чисел.

    Raises:
        ValueError: если n отрицательное.
        TypeError: если n не int (bool тоже отклоняется).

    Examples:
        >>> sum_range(10)
        45
        >>> sum_range(10, inclusive=True)
        55
        >>> sum_range(0)
        0
    """
    # Отклоняем bool: True/False — подкласс int, но семантически не число.
    if isinstance(n, bool) or not isinstance(n, int):
        raise TypeError(f"n должно быть int, получено {type(n).__name__}")
    if n < 0:
        raise ValueError(f"n должно быть >= 0, получено {n}")

    # Граница для range: range(n) даёт 0..n-1, range(n+1) — 0..n.
    stop = n + 1 if inclusive else n
    return sum(range(stop))


def main() -> None:
    """Точка входа для демонстрации."""
    print(sum_range(10))                 # 45
    print(sum_range(10, inclusive=True)) # 55
    print(sum_range(0))                  # 0


if __name__ == "__main__":
    main()
```

## Пояснения

1. **Функция вместо выражения.** Именованная функция даёт контракт (типы, докстринга, примеры) — её можно импортировать, тестировать и документировать. Голый `print(...)` этого не позволяет.

2. **Валидация типов и значений.** `range(-5)` не падает, а молча возвращает пустой диапазон → сумма `0`. Это скрытая ошибка, которую легко не заметить. Явный `ValueError` для отрицательных `n` — лучше, чем тихий неверный результат.

3. **`isinstance(n, bool)` отдельно.** Классическая ловушка: `isinstance(True, int) == True`, потому что `bool` наследуется от `int`. Без этой проверки `sum_range(True)` вернёт `1` вместо ошибки.

4. **Параметр `inclusive` keyword-only (`*`).** Заставляет вызывать `sum_range(10, inclusive=True)` — читаемее, чем `sum_range(10, True)`, где легко перепутать смысл флага.

5. **`sum(range(...))` — O(n) по времени, O(1) по памяти.** `range` ленивый, не создаёт список. Для больших `n` это важно: `sum(list(range(10**8)))` съест ~800 МБ, а `sum(range(10**8))` — нет.

## Альтернативный вариант: формула Гаусса

```python
def sum_range_formula(n: int) -> int:
    """Сумма 0..n-1 через арифметическую прогрессию — O(1)."""
    if n < 0:
        raise ValueError("n должно быть >= 0")
    return n * (n - 1) // 2
```

**Сравнение:**

| Подход | Время | Память | Читаемость | Риск переполнения |
|---|---|---|---|---|
| `sum(range(n))` | O(n) | O(1) | высокая | нет (Python int безграничный) |
| `n*(n-1)//2` | **O(1)** | O(1) | средняя (нужно знать формулу) | нет |

Для `n = 10**9` цикл `sum(range(...))` займёт секунды, формула — микросекунды. В реальном коде с большими диапазонами — только формула. В учебном — `sum(range(...))` нагляднее и меньше шансов ошибиться в формуле (например, забыть `//` и получить `float`).

## Усложнение задачи

1. **Сумма с шагом и произвольными границами:** `sum_range(a, b, step=1)` — сумма арифметической прогрессии от `a` до `b` включительно с шагом `step`. Проверьте на отрицательных `step`.
2. **Только чётные/нечётные:** реализуйте через `range(a, b, 2)` и сравните с формулой.
3. **Без `range`:** напишите `my_sum` с циклом `while` — сравните производительность с `sum(range(...))` через `timeit`.
4. **Типизация:** добавьте `@overload` для сигнатуры с `Iterable[int]` и без — чтобы `sum_range([1,2,3])` тоже работал.
5. **Тесты:** напишите `pytest`-параметризацию на краевые случаи: `0`, `1`, `True`, `-1`, `10**6`, `float`.

## Потенциальные ошибки на будущее

- **Тихий ноль при отрицательном `n`:** `sum(range(-5)) == 0` — не ошибка, а неверный ответ. Всегда валидируйте вход.
- **`bool` как `int`:** `sum_range(True)` → `1`. Ловится только явной проверкой `isinstance(x, bool)`.
- **`sum` на нечислах:** `sum(["a", "b"])` упадёт с `TypeError` — но `sum([[1], [2]], [])` сработает неожиданно. Для строгого контракта — аннотация `Iterable[int]`.
- **`range` с `float`:** `range(10.0)` → `TypeError`. Если функция принимает «число», решите: приводить к `int` (`int(n)`) или требовать `int`. Явное лучше неявного.
- **`print` в библиотечной функции:** вывод в `stdout` — побочный эффект. Возвращайте значение, печатайте в `main()` — так функцию можно переиспользовать.
