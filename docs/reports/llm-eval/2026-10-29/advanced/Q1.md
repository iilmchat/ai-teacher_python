# advanced · Q1

**Вопрос:** Почему `if x = 5:` не работает?

**Провайдер:** deepseek (deepseek-chat) · **Версия промпта:** 1

**Предупреждения политики:** нет

## Ответ

## Краткий разбор проблемы

В Python `=` — это **оператор присваивания**, а не сравнения. Выражение `x = 5` — это *statement* (инструкция), а не выражение, возвращающее значение. Поэтому его нельзя использовать там, где ожидается значение — в условии `if`. Для сравнения используется `==`. Это не баг, а осознанное решение дизайнера языка Гвидо ван Россума: он сознательно запретил присваивание внутри условий, чтобы исключить классическую ошибку из C/C++ — `if (x = 5)` вместо `if (x == 5)`, которая молча присваивает и всегда истинна. В Python 3.8+ появился оператор «морж» `:=`, который **позволяет** присваивание внутри выражения — но только явно и осознанно.

## Полное решение с комментариями

```python
# ❌ Так НЕ работает — синтаксическая ошибка (SyntaxError)
# if x = 5:
#     print("ok")

# ✅ Правильно: сравнение через ==
x = 5                      # присваивание — отдельная инструкция
if x == 5:                 # сравнение — выражение, даёт bool
    print("x равно 5")     # -> x равно 5

# ✅ Если нужна проверка «присвоить и проверить» — оператор «морж» :=
# Появился в Python 3.8 (PEP 572). Возвращает присвоенное значение.
if (y := 5) == 5:          # скобки обязательны: без них приоритет := ниже ==
    print(f"y = {y}")      # -> y = 5

# ✅ Идиоматичный «морж» — типичный случай: чтение до EOF
# (часто встречается при работе с файлами и потоками)
import io
stream = io.StringIO("строка1\nстрока2\n")
while (line := stream.readline()):   # пустая строка "" → False → выход
    print(line.rstrip())             # -> строка1 / строка2
```

## Пояснения

1. **`=` — statement, `==` — expression.** В грамматике Python `x = 5` не является выражением и не имеет значения. Поэтому `if x = 5:` парсер отвергает ещё до выполнения — это `SyntaxError`, а не `TypeError`. Ошибка возникает на этапе компиляции в байткод.
2. **Причина запрета — защита от ошибок C/C++.** В C `if (x = 5)` валидно: присваивание вернёт 5, что истинно, и ветка выполнится всегда. Такие баги ловили десятилетиями. Python выбрал строгость: либо `==`, либо явный `:=`.
3. **Оператор `:=` (walrus).** Возвращает присвоенное значение и позволяет писать `if (n := len(data)) > 10:`. Скобки нужны из-за приоритета: `if n := len(data) > 10:` распарсится как `n := (len(data) > 10)` — почти наверняка не то, что вы хотели.
4. **Типичная ошибка новичка** — путать `=` и `==` в условиях. В Python вы получите `SyntaxError` сразу, что хорошо: ошибка видна мгновенно, а не через час отладки.
5. **Стиль (PEP 8).** Вокруг `==` и `:=` ставятся пробелы (`x == 5`, `(n := len(s))`). Не используйте «морж» ради экономии строк — только когда он реально улучшает читаемость (например, в `while`-цикле чтения).

## Альтернативный вариант и сравнение

**Вариант без «моржа»** — присваивание отдельной строкой:

```python
# Классический подход без :=
stream = io.StringIO("a\nb\n")
line = stream.readline()
while line:
    print(line.rstrip())
    line = stream.readline()   # дублирование вызова — легко забыть
```

| Критерий | Без `:=` | С `:=` |
|---|---|---|
| Читаемость | Дублирование `readline()` | Компактно, один вызов |
| Риск ошибки | Легко забыть «продвинуть» переменную → бесконечный цикл | Невозможно забыть |
| Совместимость | Python 2/3, любые версии | Только 3.8+ |
| Когда выбирать | Старый код, простые случаи | Циклы с вычислением + проверкой |

Для простого `if x == 5` «морж» не нужен — он только запутает. Применяйте его там, где значение вычисляется **один раз** и используется **и в условии, и в теле**.

## Потенциальные ошибки на будущее

- **Путаница `is` vs `==`.** `x is 5` может работать для малых int (кэш CPython −5..256), но это деталь реализации — для сравнения значений всегда `==`.
- **`:=` в comprehension.** `[y := f(x) for x in data]` синтаксически допустимо, но `y` «утечёт» в объемлющую область — неожиданный побочный эффект.
- **Приоритет `:=`.** Без скобок в `if`, `while`, comprehension — почти всегда ошибка. Ставьте скобки всегда, когда сомневаетесь.
- **Сравнение с `None`.** Пишите `if x is None:`, а не `if x == None:` — последнее может вызвать перегрузку `__eq__` и работать не так, как ожидается.
