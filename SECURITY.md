# SECURITY.md — политика безопасности

> Проект: AI Teacher for Python (учебный ассистент по Python для школьников).
> Контакт для сообщений об уязвимостях: **info@ruchating.com**.

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 0.6.x | ✅ исправления безопасности |
| 0.5.x | ✅ только критические исправления |
| 0.3.x | ❌ сведения, без патчей |
| ≤ 0.2.x | ❌ только сведения, без патчей |

Исправления выходят патч-релизами (`v0.6.N`); breaking changes — только в
минорных релизах (см. `docs/CHANGELOG.md`).

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите на **info@ruchating.com** и укажите:

1. версию (`/api/v1/health` → `version`) и режим (`EXECUTOR_MODE`);
2. шаги воспроизведения и ожидаемое/фактическое поведение;
3. оценку влияния (какие данные/роли затронуты);
4. по желанию — PoC и предложение по исправлению.

Ответственность сторон:

- подтверждение получения — в течение 3 рабочих дней;
- предварительная оценка и план — в течение 7 рабочих дней;
- фикс High/Critical — в течение 30 дней (патч-релиз + запись в
  `docs/KNOWN_ISSUES.md` с новым `KI-NNN`);
- публичное раскрытие — после выхода исправления, по согласованию с автором
  сообщения (в тексте укажите, хотите ли быть упомянуты).

## Область действия

В скоупе: API и фронтенд, аутентификация/авторизация, песочница исполнения
кода (`app/core/executor.py`, `app/core/container_sandbox.py`), хранение данных
(PostgreSQL/Redis), compose-конфигурация и CI-цепочка.

Вне скоупа: уязвимости сторонних сервисов (DeepSeek/OpenAI-совместимые API,
SMTP-провайдер), DoS на уровне инфраструктуры, социальная инженерия,
устаревшие браузеры.

## Что считается уязвимостью

- обход песочницы: доступ к файловой системе/сети/процессам хоста, побег из
  контейнера-раннера, обход `RestrictedPython`;
- эскалация роли (student → teacher/admin), доступ к чужим классам/задачам/чату;
- утечка секретов (`.env`, JWT `SECRET_KEY`, ключи LLM) через API, логи, `/metrics`
  или ответы ошибок;
- SQL/command injection, XSS в чате и markdown-рендере, CSRF;
- обход rate limit и «отравление» кэша, влияющее на других пользователей.

Известные принятые ограничения (не требуют нового issue, отслеживаются в
`docs/KNOWN_ISSUES.md`): `KI-018` — `str.format`/`format_map` недоступны в
песочнице после RestrictedPython 8.5; `KI-023` — merge-gate на GitHub Free.

## Правила безопасной эксплуатации

- **TLS обязателен с v0.6.0 (S36-003):** единственный публичный вход — Caddy
  (80/443 или 8080/8443 на пилоте) с автоматическим ACME-сертификатом;
  frontend/backend наружу не публикуются. HSTS выдаётся на edge.
- **Автоматические бэкапы (S36-006):** systemd-таймер 03:00 UTC, `pg_dump` +
  gzip + опционально `age` + выгрузка в S3; метрика `BackupStale`, ночная
  проверка `restore_drill.sh`. Рабочая БД восстанавливается только осознанно
  (`--force`).
- **Образы из GHCR по digest (S36-001/002):** prod не собирается на хосте;
  `scripts/pin_images.sh` фиксирует immutable digest в `.env.prod`, деплой
  использует его. `latest` в prod запрещён.
- `.env` не коммитить (в репозитории только `.env.example`); `SECRET_KEY` и
  `DEEPSEEK_API_KEY` — уникальные, ротация при подозрении на утечку;
- **`DEBUG=false` + небезопасный `SECRET_KEY`**: приложение намеренно не
  стартует. Ключ должен быть случайным и не короче 32 символов (S34-005);
- **`DOCS_ENABLED=false`** в production: Swagger/ReDoc/`/api/openapi.json`
  не отдаются (S34-006);
- **`TRUSTED_PROXIES`**: перечислите IP/CIDR вашего reverse-proxy (Caddy/nginx).
  Только запросы от этих адресов могут задавать клиентский IP через
  `X-Forwarded-For`; для остальных заголовок игнорируется (S34-003).
  Пустой список безопасен: используется TCP-peer;
- **refresh-токен** передаётся только в теле JSON `POST /auth/refresh`,
  не в query string — токены не попадают в access-логи прокси (S34-002);
- **rate limit**: `POST /auth/login` — 5/мин на IP; `POST /auth/refresh` —
  30/мин на IP; общий — 300/мин на IP; `POST /code/execute` — 30/мин на
  пользователя; пробные проверки задачи — 20/мин на пользователя (S34-004);
- `/metrics` и `/health/*` не публиковать наружу (в nginx — 404);
- ПДн: минимум данных, retention включён, экспорт — только admin
  (`docs/PRIVACY.md`);
- зависимости: `pip-audit`/`pnpm audit` в CI, обновления — через Dependabot;
- секреты в логах маскируются (`gitleaks` в CI проверяет историю);
- образ песочницы запускать с `--network none --read-only --cap-drop ALL
  --user 65534:65534` (см. `docs/USER_GUIDE.md` и `docker-compose.prod.yml`).

## Процесс после подтверждения

1. Заводится `KI-NNN` (High/Critical — сразу, приватно до фикса).
2. Ветка `fix/KI-NNN-...`, тест-регрессия, фикс, зелёный CI.
3. Патч-релиз, запись в `CHANGELOG` (раздел «Безопасность») и в
   `docs/RELEASES.md`, уведомление автора сообщения.
