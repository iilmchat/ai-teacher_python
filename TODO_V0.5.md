## 0. Цель этапа

v0.4.0 делает продукт надёжным в эксплуатации. v0.5.0 делает его **полезным
в ежедневной работе**: ученик получает полноценный цикл «понял → написал →
проверил → понял ошибку → починил», учитель — инструменты разбора работ и
аналитики по классу, администратор — обзор действий и экспорта.

### 0.1. Критерии успеха этапа

| Критерий | Проверяемое доказательство |
|----------|-----------------------------|
| Полный цикл проверки без траты попытки | `POST /tasks/{id}/check` + кнопка «Проверить»; счётчик попыток не растёт |
| История попыток ученика | таблица `task_attempts`, `GET /tasks/{id}/attempts`, видны код и разбор по кейсам |
| Черновик не теряется | `draft_code` в прогрессе, восстановление при открытии задачи |
| Чат — рабочий инструмент | заголовки/переименование/закрепление сессий, стоп и регенерация, оценка ответа, экспорт |
| Песочница пригодна для обучения | stdin, история запусков, анализ кода, лимиты, сохранение файлов |
| Ученик управляет аккаунтом | смена пароля, e-mail/имени, удаление аккаунта, выгрузка своих данных, настройки уведомлений |
| Учитель разбирает работы | просмотр решений ученика, drill-down по назначению, правка сроков, массовые операции, объявления |
| Админ видит действия | экран журнала аудита, выгрузка аналитики, карточка пользователя, очередь модерации задач |
| Нет «мёртвого» API | все маршруты `SPEC.md` покрыты UI или явно помечены как внутренние; `KI-030` закрыт |
| Качество и доступность | e2e на новые сценарии, a11y-аудит, PWA-shell, i18n ru/en полностью, ErrorBoundary |
| Документация | обновлённые `SPEC`, `USER_GUIDE`, `CHANGELOG`, `RELEASES`, отчёты по шагам и спринтам |

### 0.2. Принципы этапа

1. **Сначала ценность для ученика.** Спринты 42–44 — ядро обучения; всё
   остальное строится поверх них.
2. **Ни одной «половины» функции.** Если в спринте есть кнопка — у неё есть
   API, обработка ошибок, пустое состояние, i18n и тест.
3. **Данные не теряются.** Черновики, история попыток, заголовки сессий.
4. **Учитель — взрослый пользователь.** Любая аналитика должна отвечать на
   вопрос «что делать дальше», а не просто показывать график.
5. **Контракт = UI.** Неиспользуемые маршруты API — дефект (см. `KI-030`).
6. **Один источник правды.** Детали задач — здесь; `RELEASES.md` хранит
   статус, `README.md` — навигацию.

При одном разработчике «параллельные» волны означают переключение между
задачами. Спринты 43 и 45 — самые независимые, их можно разнести по времени
без потерь.

## 9. Границы этапа (что не входит в v0.5.0)

- Мультитенантность (организации/школы), SSO/LDAP/SAML, SCIM.
- Биллинг, платежи, квоты и тарифные планы.
- Родительский портал, push-уведомления, мобильные приложения.
- Интеграции с LMS (Google Classroom, Moodle, LTI) — задача следующего этапа;
  в v0.5.0 есть только ручной импорт списка учеников (S46-005).
- Публичный API для внешних разработчиков, вебхуки, MCP-сервер.
- Адаптивные алгоритмы подбора задач (ML-рекомендации) — в v0.5.0
  детерминированные правила.
- Полноценный тренажёр (курсы, модули с уроками, видео) — только траектории
  из задач.
- Полный перенос токенов в httpOnly-cookie — опциональная задача S45-006,
  решение владельца обязательно.
- Глубокая интеграция с внешними сервисами хранения кода (GitHub и т. п.).

## 10. Отчётность и правила обновления плана

- Каждый шаг — отдельный отчёт `docs/reports/sprint-N/STEP-MM_<ТЕМА>.md`
  по `RULES.md` §12 (7 разделов).
- Каждый спринт — `docs/reports/sprint-N/SPRINT-N.md` по `RULES.md` §2.4,
  запись в `docs/RELEASES.md` и `docs/CHANGELOG.md`.
- Статусы задач обновляются здесь сразу после шага; оценки уточняются по
  факту.
- Если задача выросла больше чем на ~20% или меняется порядок спринтов —
  обновить этот файл и добавить запись в §12. Второй файл-плана на этот этап
  не создаётся.
- Новый блокер — сразу `KI-NNN` (следующий свободный — `KI-031`) и остановка
  шага.
